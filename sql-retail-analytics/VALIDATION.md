## Особенности исходной логики

- «Продававшиеся товары» определяются наличием чеков, а не остатками или полным ассортиментом магазина. В №1 выводится цена из Product.
- №2, №5 и №6 связывают факт продажи и факт поставки по товару и магазину. Они не устанавливают, из какой партии был продан товар, и не проверяют, что поставка предшествовала продаже. В исходных данных есть более поздние поставки; даты сохранены.
- Названия магазинов, товаров, поставщиков, адреса и ФИО не имеют ограничений уникальности. Одноимённые сущности могут попадать в одну выборку: исходные фильтры сохранены.
- №7 проверяет наличие карты у покупателя, но не её использование или дату выдачи относительно покупки. В примере все карты выданы до покупок. Запрос возвращает до двух строк; при одном товаре или полном равенстве количества продаж минимум и максимум могут совпасть в одной строке.
- №8 выбирает один товар с минимальным числом чеков, разрешая равенство по `product_id`. Товары без продаж не учитываются. Объём поставок считается только по этому товару; при равных объёмах порядок поставщиков исходным SQL полностью не определён.
- На этих данных №8 выбирает `Yogurt Cherry` (один чек в мае), но его единственная поставка датирована 1 июня 2025 года. Пустой результат корректен. Данные и период не менялись ради непустого ответа.
- Маркетинговое представление имеет детализацию по покупателю и карте: при нескольких картах суммы покупателя повторяются в отдельных строках и не должны суммироваться между картами. Представление продаж агрегирует всё время по отдельным магазинам; отдельная агрегация по форматам в нём не реализована.
- ПР1 содержит обоснование 3НФ (стр. 11–12), но также хранит вычисляемые суммы позиций и чеков. README описывает конкретные связи и справочники без безусловного заявления о строгой 3НФ. Схема не перепроектировалась.
